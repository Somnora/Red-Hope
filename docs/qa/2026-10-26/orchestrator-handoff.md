## Lessons from this session
- **Do not run a large side workflow while a gate builder runs.** On 2026-11-05 a 10-agent progress backfill (about 2.2M tokens) ran beside G1's fix round; the account hit its 5-hour limit at about 12:24 and the builder died mid-battery, voiding it.
- **A follow-up called "latent" must be checked against the reference playtest before it is deferred.** G1's SEATS case was called latent but is reachable at sol 41.61 (the Full Laboratory unlock); it cost a fix round.
- **When review rounds keep finding one more display reader of the same sim state, fix the state, not the readers.** G1's rounds 1-3 each found another reader of the per-step station set; the cure is one sim change (seats held through rationing), planned for G7.
- **After a third review round, go to the director with a short targeted round or a commit-with-known-issues choice, not another full re-run.** G1 took about 31 hours and three full gate runs before round 3; the daily job raised a LOOP ALARM on it.
- **Do not edit the vault progress notes while the 23:47 daily job runs** (23:47 to about 00:45).
- **A static Hope re-score misses the feedback loops; a `-RHConfig` preview catches them cheaply.** The balance scope re-scored B by subtracting points, but research only accrues at smoothed Hope 85 and settlers per ship read Hope above 70, so the preview's "zero the milestones" run collapsed the colony to 7 people. One 110-sol playtest with overrides (no build, about 3 minutes) found the cliff before the gate. A control run with the old values by `-RHConfig` then proves the build changed nothing else (byte-identical timeline).
- **UBT skips a source edited in the same second a build finished** (it relinks only). P2's chain sleeps 2 s, touches the file, and checks for the Compile line. **The RedHope link is not bit-reproducible** (object mtimes in the debug map), so prove a rebuild by `__TEXT`/`__DATA` (`wip-backups/p2/work/checks/dylib_cmp.py`) or install the frozen copy. A copy keeps the frozen file time, so restored sources can be newer than the installed dylib.
- **Dropped presses were frequent in P2** (6 of 17 main-scene runs, swap up to 7.8 GB, the Claude app, Brave and daemons beside the editor). Ruling 26's second-failure case came up once (`p2_mut_c1`); the orchestrator accepted it because the named clause fired in both runs.
- **The launch turn's message reaches every agent.** When James's go arrives with another message in the same turn (2026-11-03: "execute p1", then "a"), add one line to the run's notes saying what each means and that neither changes the gate, before launching.
- **Ruling 27 works on a quiet morning.** The idle gate's frame check, busy at night (ffmpeg), counted three pairs in 18 minutes at 09:38 with load 1.7-3.6.
- **An account usage limit kills every agent at once.** On 2026-10-28 the other window's limit hit mid-review and all five reviewers of E6's round 2 returned nothing. Since 00c6900 that returns `reviewersFailed`; re-run just the review (a review-only script from the gate script's preamble, the builder's report passed as a file path) rather than the whole gate.
- **A control run settles cause.** D6e's 0 W control (`-RHConfig=LiftCarW=0,TramWPerCell=0`) proved the lifts playtest shift was the draw, and the same control on -scale exposed the sort defect. Check that the control ran on the final binary (`d6e_lifts_w0_rep`, not the intermediate `d6e_lifts_w0`).
- **Never SendMessage to an agent running inside a Workflow.** The message resumes the agent outside the workflow, so its result comes back to you, and the workflow's `agent()` call waits forever. To change a running builder's instructions, let it finish. Or stop the workflow, then run the remaining phases as a new workflow, passing the builder's report in.
- **Machine load breaks the click test.** With load above about 10 (Codex, an Xcode build, ffmpeg), click runs time out at 450 s and menu steps fail. On a quiet machine the same build passes 92/92 in about 150 s. Check `uptime` before counting click runs, and ask James to pause heavy jobs.
- **`r.ForceLOD` does not reach HISM/instanced meshes; `foliage.ForceLOD` does.** Use the latter to compare LODs on kit parts.
- **Frame timing on a swapping 8 GB machine is noise.** Adjacent pairs swing from -8 to +10 ms. Only quiet pairs mean anything, and a director waiver must quote them honestly.

- **Other heavy jobs on this Mac starve the counted runs.** On 2026-11-06 another project's ffmpeg render (about 11:55 to 12:20, load near 30) made `g2a_a2_flash2` sample only 12 frames on a G1 step and fail. Ask James to hold renders and other heavy jobs while a gate runs, and say so in each launch report.
- **Free space on / falls during a gate as macOS adds swap files** (12 GB at launch to 7.2 GB five hours later on 2026-11-06, with 11 GB of swap). The builder refuses counted runs below 6 GB. The simulator dyld cache (`/Library/Developer/CoreSimulator/Caches/dyld`, about 5.6 GB, removed with `xcrun simctl runtime dyld_shared_cache remove --all`, rebuilt on the next simulator boot) and the npm, pip, uv and Homebrew caches are safe to clear first; nothing of James's is.
- **A person's input spoils counted runs, and Universal Control counts.** A real mouse movement over the game window moves the pointer the hover check reads (G2a attempt 1, `g2a_r2_mut_hyst`), and input from James's other devices through Universal Control changed the shown floor during `g2a_r3_click1`. Read the HID idle time before and after every counted run and pmset's userActivity assertions in its window; ask James to keep off this Mac and its linked devices while click and flash runs are on.
- **A stop_reason that begins "none" is not a stop.** A closing-step script that treated "none: ..." as a stop skipped G2a round 2's review; test `t !== '' && !/^none\b/i.test(t)`.
