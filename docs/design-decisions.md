# Design Decisions — The Red Hope

Format: each entry records the decision, its origin (agent-proposed / director-approved / director-directive), and why.

## Standing directives (director, from kickoff — 2026-07-04)

- Greenfield rebuild. The Three.js prototype is a design-learnings reference only; never port, adapt, or reference its code.
- Everything is real 3D geometry. Gray-box primitives until an art pass is explicitly scheduled. No sprites/billboards of any kind, no camera workarounds.
- Simulation decoupled from presentation from day one; sim must run headless and faster than real time.
- Data-driven everything: balance values in DataTables/curves/config, never hardcoded.
- Mental-health theme: prevention-focused systems, abstracted consequences, never graphic, never trivialized. Anything in this area is flagged for the director's explicit review before implementation.
- If a prototype pattern conflicts with idiomatic UE5 architecture, UE5 idiom wins.
- Small, reviewable increments; never more than one approved step ahead.

## Approved — 2026-07-04 (agent-proposed, director-approved)

Full rationale for each in `docs/step1-digest-and-recommendations.md`.

1. **Time model:** real-time with pause, stepped acceleration, fixed-timestep sim; latency denominated in sim-time; orders queue while paused.
2. **Placement:** square grid (~2 m cells), multi-cell footprints, 90° rotation; buildings snap, agents move freeform on navmesh.
3. **Colonists:** named individuals with cohort-depth simulation; specialists get extra depth.
4. **Embodiment:** disembodied mission control ("the Program"); no avatar; the entity gets re-chartered diegetically in Phase 3.
5. **Failure:** survive-the-consequences resilience; hard fail only at absolute edges; ironman as later difficulty option.
6. **Automation:** goals + priorities + policy toggles, no player programming at v1; task system data-driven so scripting can bolt on post-v1.
7. **Manifest:** mass budget + discrete packages; no volume Tetris; indivisible oversized items later.
8. **Solidarity Dilemma:** driven by a live Earth-relations sim (tension model + trade-ledger verification), not an event tree.
9. **Map model (adopted as the formal ninth open question):** one authored heightmap region, hand-placed data-defined deposits; procedural is a post-v1 sandbox question.
10. **Logistics:** hybrid — power/water/gases flow instantly in connected networks; solids are physical stockpiles moved by haulers.
11. **Hope:** derived, non-spendable index; explicit actions trade other resources for Hope inputs, never spend Hope itself.
12. **Identity axis:** accumulates silently from Phase 1, surfaces as a visible instrument in Phase 3.

**STANDING DESIGN RULE established this session — the death-spiral guardrail:** any Hope→work→Hope feedback must be *carrot-first and recoverable*. ### D5a as built (2026-10-17)

- **The rule.** A machine on the day shift spends only the DAYLIGHT SHARE of each step: its production budget and its above-idle draw are both scaled by it, and it draws idle power otherwise. At night the batch pauses (nothing is lost, nothing new starts), including a Borer batch fuelled by H2 (the fuel is paid, the work waits for sunrise). Manual OFF still overrides it. Shedding and the load priority order are unchanged: a resting machine keeps its `Loads` entry at idle draw. It is offered only where a machine has something to pause: `PowerDraw > PowerIdle` and a recipe or bore work. That derives to exactly Forge, Electrolyzer, Water Plant, Ice Drill and Borer; never life support, rooms, pads or storage.
- **The window and the defaults are data, with no new row-struct column.** `RH_Config.csv`: `DayShiftStartFrac` 0.25 and `DayShiftEndFrac` 0.75 (where `RH_Curve_SolarDiurnal` leaves and returns to 0), `DayShiftDefaultsOn` 1 (the A/B master switch: `-RHConfig=DayShiftDefaultsOn=0` is the old all-hours colony), and one `DayShiftDefault_<Def>` row per machine that starts on the shift (Forge 1, Electrolyzer 1). The plan had a `DayShiftDefault` column on `FRHBuildingRow`; a per-def config row needs no struct change, no director compile before the DT sync, and a sweep can flip any machine (`-RHConfig=DayShiftDefault_WaterPlant=1`). A bad window (not 0 <= start < end <= 1) logs an Error and falls back to 0.25..0.75. `DT_Config` synced headlessly: 173 -> 178 rows. `AddBuilding` applies the default, so every placement path (uplink Build, debug, showcase) gets it.
- **Era parity, by construction.** A step's daylight share is `(D(T1) - D(T0)) / (T1 - T0)` with `D` the cumulative daylight seconds, so work and draw are linear in dt: 12 sol-hours of work per sol at dt 60 s aligned, dt 1 s, and dt 60 s offset by 30 s (all `12.000000`). The end-of-step solar gate (the 587/2963 idiom) was rejected: the era band would get 10.8 h against 12.
- **In-game burst parity.** The clock advances the whole frame before the sim runs, so up to four era steps (or 32 agent steps) of one frame would read the same end time. `Tick` now gives each step its own window end (`StepEndOverride`, cleared after the loop); the commandlet leaves it unset. Pinned by DS7e through the real clock and sim ticks: a four-step frame across sunset works 1.8 h (90 s of daylight), across sunrise 3.0 h (150 s). Without the override the same frames read 0 h and 4.8 h (checked by mutation).
- **The dawn lag is measured, not hidden (DS7d).** Production reads the shed state the previous step's power pass set, so a resting machine that was shed overnight loses its first dawn step: 1.2 h (the whole step) in the era band, 0.02 h at dt 1 s. Scenario: bank zeroed every night step, a Water Plant off the day shift so the grid sheds the Electrolyzer too, eight arrays by day. Sunrise-to-sunset work is 10.8 h (era) against 11.66 h (dt 1 s), a gap of 0.86 h; the documented tolerance is one era step (1.2 h). The gate is not "era-parity-exact" for a colony that is shed at dawn; that residual is the one-step power lag, which predates D5a.
- **Save v33, strict.** `bDayShift` is serialized inline in the building record (4 bytes a building: every `Colony saved` line grows by 4 x buildings, 1468 -> 1472 for the baseline's one). `LoadColony` refuses any other version, so v32 saves refuse loudly, including the quick and auto slots; no v32 load path was added (director decision). A v32-stamped file is refused in the suite. Nothing else is saved: the share, the resting state, the guide step and the halo are derived.
- **Presentation (placeholder copy, inventory D114-D122).** A `DAY SHIFT: ON/OFF` button under the breaker on a finished eligible machine's card (a direct sim toggle like the breaker); the status line reads `DAY SHIFT - resting until sunrise (idle draw, batch paused)` at night and `DAY SHIFT - works while the sun is up, rests at night` by day, and the batch line gains `(paused until sunrise)`; the build drawer says which machines start on the shift and which can take it; the POWER panel gains `DAY SHIFT: n machine(s) resting until sunrise`; audio treats a resting machine as idle; `RH.DayShift <Id> <0|1>`.
- **The guide teaches it as an interrupt.** `POWER / Put machines on the day shift` ranks after FOOD and before the ice steps, applies from the first night the grid sheds while a finished heavy machine still runs all hours, and lights the DAY SHIFT button on the machine the player has selected while it is off the shift. It names the first such machine. It ends at sunrise with no "Done" toast (a morning is not the player's doing); resolving it at night gets the usual tick. There is no separate tip card.
- **No flashing.** The shed flag alternates every sim step while the bank scrapes empty (the suite sees it flip 6 times in one ten-step night). So the guide keys on a latch instead: `GetLastBlackoutNight()` is written by `StepPower` when it sheds after sunset, never saved, read by nothing in the sim, reset on load. The halo is a steady function of that latch, the sun, and the selected machine's flag. **The reviewed design latched in the deck from `ShedCount > 0 && BatteryWh <= 0`; the live smoke showed that pair is never true at the end of a step** (a shed step leaves a sliver of charge, the next step clamps it to 0 with nothing shed), so the guide never fired. The latch moved into the sim and keys on `ShedCount > 0` at night, which already implies an empty bank. DS8 pins it: the flag flipped 6 times, the latch changed once.
- **Verified** by the new `-dayshift` suite (25 checks, fails loudly): live DT_Config rows read from the table alone; the default set and the derived eligible set as exact sets over the building table; the solar curve's edges; the daylight helper (cases, wrap, points); defaults and refusals on real placements; the noon / night rest / dusk partial / shift-off / manual-OFF arithmetic, exact to 1e-9 (a night rest leaves the batch at 0.8000 h and the load at idle); era parity at three alignments; DS7d; DS7e; the bank through the night (5520 Wh at dawn on the shift against 16500 Wh needed with it off, 3 shed steps); the resting count and the night key; a v33 round trip with every mutable flag flipped, and the v32 refusal.
