# Design Decisions — The Red Hope

Format: each entry records the decision, its origin (agent-proposed / director-approved / director-directive), and why.

## Standing directives (director, from kickoff — 2026-07-04)

- Greenfield rebuild. The Three.js prototype is a design-learnings reference only; never port, adapt, or reference its code.
- Everything is real 3D geometry. Gray-box primitives until an art pass is explicitly scheduled. No sprites/billboards of any kind, no camera workarounds.
- Simulation decoupled from presentation from day one; sim must run headless and faster than real time.
- Data-driven everything: balance values in DataTables/curves/config, never hardcoded.
- Mental-health theme: prevention-focused systems, abstracted consequences, never graphic, never trivialized. Anything in this area is flagged for the director's explicit review before implementation.
- If a prototype pattern conflicts with idiomatic UE5 architecture, UE5 idiom wins.
- Small, reviewable increments; never more than one approved step ahead.

## Approved — 2026-07-04 (agent-proposed, director-approved)

Full rationale for each in `docs/step1-digest-and-recommendations.md`.

1. **Time model:** real-time with pause, stepped acceleration, fixed-timestep sim; latency denominated in sim-time; orders queue while paused.
2. **Placement:** square grid (~2 m cells), multi-cell footprints, 90° rotation; buildings snap, agents move freeform on navmesh.
3. **Colonists:** named individuals with cohort-depth simulation; specialists get extra depth.
4. **Embodiment:** disembodied mission control ("the Program"); no avatar; the entity gets re-chartered diegetically in Phase 3.
5. **Failure:** survive-the-consequences resilience; hard fail only at absolute edges; ironman as later difficulty option.
6. **Automation:** goals + priorities + policy toggles, no player programming at v1; task system data-driven so scripting can bolt on post-v1.
7. **Manifest:** mass budget + discrete packages; no volume Tetris; indivisible oversized items later.
8. **Solidarity Dilemma:** driven by a live Earth-relations sim (tension model + trade-ledger verification), not an event tree.
9. **Map model (adopted as the formal ninth open question):** one authored heightmap region, hand-placed data-defined deposits; procedural is a post-v1 sandbox question.
10. **Logistics:** hybrid — power/water/gases flow instantly in connected networks; solids are physical stockpiles moved by haulers.
11. **Hope:** derived, non-spendable index; explicit actions trade other resources for Hope inputs, never spend Hope itself.
12. **Identity axis:** accumulates silently from Phase 1, surfaces as a visible instrument in Phase 3.

**STANDING DESIGN RULE established this session — the death-spiral guardrail:** any Hope→work→Hope feedback must be *carrot-first and recoverable*. ### D5a as built (2026-10-17)

- **The rule.** A machine on the day shift spends only the DAYLIGHT SHARE of each step: its production budget and its above-idle draw are both scaled by it, and it draws idle power otherwise. At night the batch pauses (nothing is lost, nothing new starts), including a Borer batch fuelled by H2 (the fuel is paid, the work waits for sunrise). Manual OFF still overrides it. Shedding and the load priority order are unchanged: a resting machine keeps its `Loads` entry at idle draw. It is offered only where a machine has something to pause: `PowerDraw > PowerIdle` and a recipe or bore work. That derives to exactly Forge, Electrolyzer, Water Plant, Ice Drill and Borer; never life support, rooms, pads or storage.
- **The window and the defaults are data, with no new row-struct column.** `RH_Config.csv`: `DayShiftStartFrac` 0.25 and `DayShiftEndFrac` 0.75 (where `RH_Curve_SolarDiurnal` leaves and returns to 0), `DayShiftDefaultsOn` 1 (the A/B master switch: `-RHConfig=DayShiftDefaultsOn=0` is the old all-hours colony), and one `DayShiftDefault_<Def>` row per machine that starts on the shift (Forge 1, Electrolyzer 1). The plan had a `DayShiftDefault` column on `FRHBuildingRow`; a per-def config row needs no struct change, no director compile before the DT sync, and a sweep can flip any machine (`-RHConfig=DayShiftDefault_WaterPlant=1`). A bad window (not 0 <= start < end <= 1) logs an Error and falls back to 0.25..0.75. `DT_Config` synced headlessly: 173 -> 178 rows. `AddBuilding` applies the default, so every placement path (uplink Build, debug, showcase) gets it.
- **Era parity, by construction.** A step's daylight share is `(D(T1) - D(T0)) / (T1 - T0)` with `D` the cumulative daylight seconds, so work and draw are linear in dt: 12 sol-hours of work per sol at dt 60 s aligned, dt 1 s, and dt 60 s offset by 30 s (all `12.000000`). The end-of-step solar gate (the 587/2963 idiom) was rejected: the era band would get 10.8 h against 12.
- **In-game burst parity.** The clock advances the whole frame before the sim runs, so up to four era steps (or 32 agent steps) of one frame would read the same end time. `Tick` now gives each step its own window end (`StepEndOverride`, cleared after the loop); the commandlet leaves it unset. Pinned by DS7e through the real clock and sim ticks: a four-step frame across sunset works 1.8 h (90 s of daylight), across sunrise 3.0 h (150 s). Without the override the same frames read 0 h and 4.8 h (checked by mutation).
- **The dawn lag is measured, not hidden (DS7d).** Production reads the shed state the previous step's power pass set, so a resting machine that was shed overnight loses its first dawn step: 1.2 h (the whole step) in the era band, 0.02 h at dt 1 s. Scenario: bank zeroed every night step, a Water Plant off the day shift so the grid sheds the Electrolyzer too, eight arrays by day. Sunrise-to-sunset work is 10.8 h (era) against 11.66 h (dt 1 s), a gap of 0.86 h; the documented tolerance is one era step (1.2 h). The gate is not "era-parity-exact" for a colony that is shed at dawn; that residual is the one-step power lag, which predates D5a.
- **Save v33, strict.** `bDayShift` is serialized inline in the building record (4 bytes a building: every `Colony saved` line grows by 4 x buildings, 1468 -> 1472 for the baseline's one). `LoadColony` refuses any other version, so v32 saves refuse loudly, including the quick and auto slots; no v32 load path was added (director decision). A v32-stamped file is refused in the suite. Nothing else is saved: the share, the resting state, the guide step and the halo are derived.
- **Presentation (placeholder copy, inventory D114-D122).** A `DAY SHIFT: ON/OFF` button under the breaker on a finished eligible machine's card (a direct sim toggle like the breaker); the status line reads `DAY SHIFT - resting until sunrise (idle draw, batch paused)` at night and `DAY SHIFT - works while the sun is up, rests at night` by day, and the batch line gains `(paused until sunrise)`; the build drawer says which machines start on the shift and which can take it; the POWER panel gains `DAY SHIFT: n machine(s) resting until sunrise`; audio treats a resting machine as idle; `RH.DayShift <Id> <0|1>`.
- **The guide teaches it as an interrupt.** `POWER / Put machines on the day shift` ranks after FOOD and before the ice steps, applies from the first night the grid sheds while a finished heavy machine still runs all hours, and lights the DAY SHIFT button on the machine the player has selected while it is off the shift. It names the first such machine. It ends at sunrise with no "Done" toast (a morning is not the player's doing); resolving it at night gets the usual tick. There is no separate tip card.
- **No flashing.** The shed flag alternates every sim step while the bank scrapes empty (the suite sees it flip 6 times in one ten-step night). So the guide keys on a latch instead: `GetLastBlackoutNight()` is written by `StepPower` when it sheds after sunset, never saved, read by nothing in the sim, reset on load. The halo is a steady function of that latch, the sun, and the selected machine's flag. **The reviewed design latched in the deck from `ShedCount > 0 && BatteryWh <= 0`; the live smoke showed that pair is never true at the end of a step** (a shed step leaves a sliver of charge, the next step clamps it to 0 with nothing shed), so the guide never fired. The latch moved into the sim and keys on `ShedCount > 0` at night, which already implies an empty bank. DS8 pins it: the flag flipped 6 times, the latch changed once.

### The grand vision: four rulings (2026-10-18)

Asked how Red Hope could become as grand as SimCity (giant Mars cities, deep trade, territories), the director ruled:
1. **No combat.** Conflict stays trade, espionage, politics and resilience. This confirms the brief's v1 non-goal and extends it past v1:
   - defence means shielding, shelters, sealed compartments and protected convoys;
   - offence means leverage: embargoes, covert operations, competition for colonists through Hope.
2. **Thousands of people.** The city targets a population in the thousands. That needs a population model with individuals near the camera and aggregates beyond it, so it comes first.
3. **Several regions.** Rival settlements get their own territories on a regional map, not one shared valley.
4. **Start with step 1, the living city:** roads, rover traffic, districts, and the scalable population model.
5. **Politics stays (director, same day: "we should still have politics").** No combat does not mean no conflict. Politics is how conflict happens in Red Hope, and it grows with the city:
   - **Outside:** Earth, the CEO arc, the Solidarity Dilemma and the identity axis; rivals with their own regions, with diplomacy, treaties, trade blocs, embargoes and covert operations; the endings.
   - **Inside (new with a city of thousands):** districts and groups with their own interests, and the brief's social threats (factions, strikes) at city scale. The form of civic voice (councils, elections or another) is an open question for when the city exists.

The order after that, agreed in the same exchange:
- 2: going deep (tunnels, transit, cavern districts, atriums);
- 3: economy (markets, exchange rates, regional specialization, a Martian currency);

### C4, roads: how they are built, and one deviation from the plan (2026-10-18)

Roads are the first real path network in the sim. What C4 settles:
- **You draw a road from point P to point Q.** It goes up the uplink with the usual lag as a `BuildRoad` order carrying both end points. The graph is integer all the way: nodes sit on the 2 m road grid, edge lengths are whole centimetres, and every tie falls to the lower Id.
- **The bill is paid up front, the labour is done by robots.** The order takes `RoadStructKgPerMeter` (2 kg/m) of Struct out of the stores in one go, or is refused and takes nothing. There is no haul leg. Each new edge is then a labour-only Build task for a Fabricator, at `RoadBuildMetersPerHour` (placeholder).
- **Roads and buildings keep clear of each other from both sides.** A footprint may not overlap a built road, a road being built, or the strip of a road order still in flight; a road may not run through a building, a site or a building order in flight.
- **Robots drive roads 1.6x faster.** A trip goes straight to an entry node, along built edges, then straight from an exit node to the target. The road is used only when it is strictly quicker than the straight line, by a speed-free integer test. A road demolished mid-trip costs the robot its speed bonus, not its way.
- **Both brains share one movement helper.** With no built road it is exactly the old `MoveToward` call, so a colony without roads is unchanged. There is no starter road in the default colony.
- **Not in C4 (follow-up):** demolishing and salvaging a road from the deck, edge marker posts, and a partial-fill look for a road under construction.

**Deviation from the plan, for the director.** The C4 row of the living-city plan says "era mode learns road distance and hauler throughput". It does not. Era logistics keeps its teleport model: material moves with no distance and no hauler capacity, so there is no road distance for it to learn. Era mode instead refuses to start while a road edge is under construction (the era band parks the fabricators, so it would never finish), and the agent/era ledger parity bar is checked with the roads finished first. Roads make the agent band quicker and so closer to era, never further. Teaching era mode distance and throughput would be a change to the whole logistics model, not to roads, and belongs with the cargo rovers (C6), when there is real traffic to be faithful to.

### C5a, districts and demand: what it settles, and where it chose (2026-10-19)

The design and its adversarial review are `docs/qa/2026-10-19/c5-districts-design.md` (the C5a section as amended by the review). C5a is data, painting, names, membership, a demand readout, the overlay and the City panel. It is inert until a district is painted: no existing suite paints one, so no existing output moves. Save version 37.

- **A district is a Kind painted on ground or on a floor.** Five kinds: Homes, Industry, Farming, Research, Civic. On the surface it is a set of 10 m lattice cells (the habitat bays' own lattice, a cell spanning [10k - 5, 10k + 5) m), painted as rectangles of at most 32 x 32 cells, every cell inside grid coverage. Underground it is a whole floor, which must be reached by the shaft. A cell, and a floor, belongs to at most one district.
- **The orders.** `PaintDistrict` (same Kind joins the one district it overlaps and keeps its Id; a rectangle over another Kind, or over two districts, is refused; ground already held is refused), `EraseDistrict` (the whole district; its Id is never reused), `RenameDistrict` (the text rides in a new `FString Text` on the command: trimmed, control characters dropped, capped at 32 characters, never empty, case-sensitive so "Gale" and "gale" are two names). Every verb rejects with a reason. An unknown verb is now refused too ("Unknown order '...'"): it used to fall through to the "executed" broadcast.
- **Names** are a hard-coded array of forty Martian place names picked by district Id, then `II`, `III`, ... after the forty. Not a data table.
- **One district per building.** A building belongs to the district holding its anchor lattice cell: bay 0 (the GridMin cell) of a habitat shell, the footprint centre of anything else; underground, its floor's district. A shell is never split: its bays and its residents belong to its building's district, whichever districts its bays reach into. A station module inside a bay is its own building and takes its own cell's district. A colonist belongs to their home's district. Erasing a district leaves no one homeless; membership is derived.
- **Membership is derived, lazily, and verified.** Two caches, rebuilt only when read: the ground (cell and floor to district, keyed on the districts' version) and the membership (building to district, per-district buildings, bays and residents, keyed on districts, zoning, colonists, furniture and the building set). `-RHVerifyCaches` re-derives both every time one is reused and logs an error on a difference. Beds and seats are not cached (rating and power move them every step): `GetDistrictCounts` reads them live. Beds are CERTIFIED beds, by the `GetHousingCapacity` rule (a rated floor's; a rated habitat's once the vault is certified); seats are the working stations' (rated homes only).
- **The demand readout is colony-wide**, a pure function of state, and nothing acts on it yet. Housing shares `GetImmigrationCount`'s terms (it is now `min(raw, room)` with the two halves public): settlers need `min(FreeBeds - ReserveBeds, ComfortCapacity - Population)`, the Big Arrival needs `FreeBeds >= BigArrivalFreeBeds`; the headline is the larger shortfall and names which term binds. Before the vault is certified surface beds lift the comfort term but not the free-bed one, so the free-bed term binds then. Jobs is the unemployed share and the seats short; Services is the coverage gap of every room function that earns Hope (the bar is the share of the Rooms bonus left on the table); Air is the share of residents in homes on short rations (any leg: the bar reads food or water shortages too, and the prose names the scarcest leg), with the oxygen margin in sols per home. Per-district rows show counts only.
- **A bug fixed on the way.** `CommandId` was never saved, so every loaded order was Id 0 and the deck's cancel removed the first queued order. It is now serialized, and a load raises the counter past the loaded Ids.
- **Deviations from the design text.** `EraseDistrict` takes an Id only (no erase-rectangle). The DISTRICT paint mode is a fourth tab beside ZONE / FURNISH / WALLS, and the City panel carries the same kind chips. The paint ghost and the district overlay are debug-draw and a procedural mesh like the roads: the wash is the glass material (`M_DomeGlass`) driven as a matte tint.


### C5b, growth: what it settles, and where it chose (2026-10-19)

The design is `docs/qa/2026-10-19/c5-districts-design.md`, section C5b-R (it replaces the original C5b, which the adversarial review blocked: growth issuing uplink orders built by robots plus an instant path in era would lock out 60x, break band parity, make the reserve uncheckable and leave colony orders unidentifiable after a load). Save v38. Inside HOME and CIVIC districts the colony builds for itself (the Q2a ruling); the player still places production, power, life support and anything special.

- **Growth is a project record, not an order.** `FRHGrowthProject`: the district, the kind (SurfaceModule | FloorCells | CivicRoom), the target (a lattice rectangle and the network it extends, or a floor and cells, or a cell or bay and a room row), the bill (resource to kg, the air for the new bays or cells included) and TotalSols / RemainingSols. No uplink order, no construction site, no robots: CanEnterEraMode is never affected and the agent and era bands run the same code (`StepCityGrowth`, after `StepBigArrival`, at the same place in both).
- **When.** At each sol boundary (the first step whose end falls in a new sol, a threshold on the monotone clock) at most ONE project starts colony-wide: districts round-robin by Id from a saved cursor; a district with an open project or its growth switch off is skipped. No start while any home is on short rations or smoothed Hope is Failing. Homes need the city's Housing shortfall (`HousingBedsShort`) above zero, net of the beds already under way; Civic needs a coverage gap on a CivicService function, counting rooms already under way (so two Civic districts do not both build the same room).
- **The bill is whole and atomic.** Per resource: free = uncommitted holdings - the open quota's bill - its reserve (GrowthReserveStructKg 1,000 of Struct; GrowthReserveO2Sols 10 sols of the whole colony's breathing for Oxygen; none for the rest). Uncommitted is C4's rule: completed buildings on linked floors plus the pool, never a construction site's hopper. The whole bill is taken at the start, or no project starts.
- **What it builds.** Surface Homes: the next Habitat Bay module of at most 2 x 2 bays on free lattice cells inside the district, edge-adjacent to a RATED, not door-sealed network with a bay in the district, touching no other shell, every bay centre covered, off roads and buildings; candidates by squared lattice distance to the network root, then (X, Y), the larger module first at one anchor. Underground Homes: GrowthCellsPerProject (4) cells on a rated floor, carved directly. Both are zoned Living and given GrowthBunksPerHome (2) bunk beds a bay or cell. Civic: the worst-covered CivicService function (ties by lexical name) in a free cell or bay of the district, furnished with its `CivicFurniture` recipe, after an adjacency check (nothing within two steps emits what the new room refuses or refuses what it emits); a cell is carved if a Civic floor has none free. A CivicService row must never emit Odor (checked at boot, refused when planning).
- **Done.** RemainingSols counts down linearly. In one step the site is re-checked (placement without the material check), then the building is added, the cells carved, the rooms zoned and furnished directly, and the new air filled from the bill so the home stays rated. A site that no longer fits refunds the whole bill; so does erasing the district.
- **Data.** New RH_Rooms columns `CivicService` (TRUE for Dining and Infirmary) and `CivicFurniture`; seven Growth rows in RH_Config (the six asked for plus GrowthBunksPerHome).
- **Deviations and open points, for the director.** (1) A surface network's air push is a flat `O2FillRateKgPerHour`, so past about 240 bays its leak (2 kg a bay a sol) outruns the push and it loses its rating on its own; growth keeps extending it (the rules say nothing else), so a big enough Homes district can grow a network out of its own air. A cap, or a push that scales with bays, is a follow-up. (2) Homes growth runs no adjacency check (the plan puts it on Civic only): on a floor the new cells land where the spiral says, and beside Gardens they cost Hope. (3) The growth switch is instant, like the machine switches, not an uplink order. (4) The surface adjacency term of the Hope index looks emitters up by position (twelve cells) instead of comparing every pair: the same pairs (the -scale sink digest is identical), and a Hope read with 500 grown bays and a hundred emitters drops from 0.42 ms to 0.13 ms.

### C5d, the City / Earth share and production-aware life support: what it settles, and where it chose (2026-10-19)

- **The share.** `CityShare` in 0..1, a saved, colony-wide policy value, set at once (like the growth switch) from the City panel (five chips, 0 / 25 / 50 / 75 / 100% city, labelled "CITY <-> EARTH", placeholder D155) or `RH.Growth share <0..1>`. It is a pure function of state: deterministic, linear in time, and the same in the agent and era bands. `GetGrowthAvailability` reports the held-back bill (`QuotaBill`) and the whole one (`FullBill`).

Settler ships are capped to the most people every leg carries (closed form, `GetSettlerSupportRoom`), the log says when a ship is held, and the City panel's Rations line says so (D156). *(C5e then tightened the settlers' side: see below.)* The Rations prose covers the production case too (D153).

The old lean state (sol 85, 8 people, oxygen 30 a sol against 81, 1,510 kg in the pool) passes at 10 sols (1,510 >= 10 x 51) and is refused only above 29.6. So the cover has its own row, 40 (about one supply round, the soonest an Electrolyzer kit can come), and `BigArrivalLifeSupportSols` still sets C5c's separate stock check (its pin is unchanged). Make the cover 10 and production stops mattering.

The wave is held on oxygen production at 75% and 100% (107 kg a sol made against 166 drawn at 113 people, 1,080 kg in the pool, the growth projects having spent the rest on new cells' air); at 25% it has no beds. - **Open points.** The several-dozen population at 110 is not reachable by the dial alone for this reason: it needs the player's farms and electrolyzers. Settlers' provisions (the wave brings 50 kg a head, a ship's settlers none) are unchanged.

### D2, more shafts: what it settles, and where it deviated (2026-10-21, not yet committed)

Built from `docs/qa/2026-10-21/d2-shafts-design.md` (sections 1-10 as amended by its REVISION, which wins where they differ). Save **v44**, strict (W1 took v43). A list of shafts, each with its own head, depth, bore target, carve queue and anchoring Borer, on shared floors (one lattice per level). With one shaft nothing moves: every battery line is identical except the eight lines that print the save version.

**Deviation accepted 2026-10-21 (the director's option a): reach is floor-wide.** Per-dig reach is deferred to D6.

> **What the plan said.** "A floor's cells are reached when a shaft that reaches that floor touches them" (`going-deep-plan.md:36`). That would make each separate dig its own place: its own air, its own rating, its own reach.
>
> **What D2 builds instead.** A floor is still one place, however many digs it has. Once any shaft reaches floor -1, the whole of floor -1 counts as reached: you can build on any carved cell, it has one air supply, one Livable rating, one district and one commute anchor. Which shaft "touches" a dig only decides which shaft head a robot or a colonist uses. It never decides whether the dig can be used.
>
> **What you will notice:**
> - **A dig with no air filter is rated through another dig's filter.** Air filters count anywhere on the floor (`IsFloorCirculated`), and so does the size minimum (`bBigEnough`). So a two-cell dig under the new shaft is Livable the moment the main dig is.
> - **A new shaft links nearby surface habitats to floor -1's air**, even before it has dug anything on -1. The habitat link is "a bay near any shaft head that has reached floor -1, while floor -1 is rated" (`IsBayNearShaftHead`, used by `IsNetShaftLinked` and the demolish check).
> - **(R2) Commutes between two digs on one floor cost 0 m.** A colonist who lives in one dig and works in the other is "on the same floor", and a same-floor commute is already 0 today. Floor residents have no cell of their own (only `HomeLevel`), so D2 cannot measure that walk.
>
> **The alternative: per-dig reach.** Each 4-connected dig that a shaft touches becomes its own place. It would fix the three effects above, and cost a re-key of every Level-keyed store (`FloorO2Kg`, `RatedFloors`, `FloorsNotedSmall`, `FloorRoomCells`, `FloorClimate`, the districts' `FloorOwner`, the colonist `HomeLevel`, `CarveQueue`, growth targets and queued orders), a merge rule for D3's tunnels, and a change to `deep.log` (D1's painted island would become unreached): two to three sessions with the battery at risk.
>
> **Recommendation (taken).** Keep reach floor-wide in D2. Move per-volume air and reach to D6 (caverns), and give floor homes a cell there so the commute can see digs (D4/D6). The two effects are pinned by `-shafts` (SH11 and SH11b), so changing the rule later is a visible, tested change.

The bar is the usual 5% ledger over 10 sols with two shafts (SH12): the Borer ledgers agree (40 + 40 cells in both bands). Era bores and carves every shaft through the same `StepProduction` code, in the same order, and does not refuse while a shaft is being sunk.
- **Shaft 0's column keeps today's behaviour for floor buildings** (O4's known gap). Tests place floor buildings at the head, so refusing (0,0) would move battery lines. A floor building on the column of a shaft k > 0 is refused ("That is a shaft column"), and SinkShaft refuses a column with a building on it.

### D3, tunnels: what it settles, and where it deviated (2026-10-21, not yet committed)

Built from `docs/qa/2026-10-21/d3-tunnels-design.md`, in the order of authority the director set: the DIRECTOR ANSWER, then the REVISION (with its option-(c) table), then the PROFESSOR REVIEW, then the original design. **Q-A (c), 2026-10-21: tunnels only.** Save **v45**, strict (D2 took v44). With no tunnel nothing moves: every battery line is identical except the nine lines that print the save version, and the new `tunnels.log`.

**What D3 builds (option c).** A painted line of ordinary carved lattice cells that joins digs on one floor, carved by the Borer.
- **The order.** `DigTunnel` (`Level`, `Location` = A, `LocationB` = B, snapped to the lattice) and `CancelTunnel` (`Value` = the tunnel's Id). The preflight (`CanDigTunnel`, also what the deck's brush pre-checks) runs again at execute time and refuses, each with a reason: a floor no shaft reaches; a chain under 2 or over `TunnelMaxCells` cells; a start that is carved or has no carved 4-neighbour ("start a tunnel at the edge of a dig"); any chain point already carved; any chain point a shaft column; any chain point an uncarved point of another open tunnel; more than `MaxOpenTunnels` open. No bill: the cost is Borer work.
- **The chain** is literal and derived: an L from A along X to (B.X, A.Y), then along Y to B, both ends included (|dx| + |dy| + 1 points). The record (`FRHTunnel`: Id, RegionId, Level, A, B, two-ended, cancelled) is all that is saved. `bTwoEnded` is set when B stands beside a carved cell; then B's end is carved too.
- **Carving.** Each cell is one `CarveCell` batch (3 sol-hours, 500 W or H2, 1,200 kg spoil at the Borer): same recipe, same cell. After bore and the carve queue found nothing, the Borer of shaft S scans open tunnels by Id on floors S reaches and takes the A front if `ServingShaft` of the front's carved neighbour is S, else the B front (two-ended). A tunnel starts a batch only while its uncarved points outnumber its batches in flight. The work record is `(2, Id)` for the A end and `(3, Id)` for the B end, so `PendingBoreWork` keeps its `FIntPoint` format and the bore-in-flight scan (X == 0) is unchanged. At completion the cell is the first uncarved chain point from the recorded end, read then, appended through `AppendCarvedCell`: ordinals stay add-only and every cell grows from a cell carved before it.
- **O9 extended.** SinkShaft refusal 8 gains "an uncarved point of an open tunnel", so a column cannot land mid-chain and strand it. A cancelled tunnel stops protecting its rock once no batch is in flight.

### D4, transit: lifts, capacity and robots below: what it settles, and where it deviated (2026-10-21, not yet committed)

Built from `docs/qa/2026-10-21/d4-transit-design.md`, in the order of authority the director set: the DIRECTOR ANSWER, then the REVISION (items 1-10 and the adopted optional items), then the PROFESSOR REVIEW, then the draft. **Q-A (a), Q-B (a), 2026-10-21:** the first lift car costs 400 kg of Struct (the config row `FirstLiftFitStructKg` stays at the price of every car, `LiftFitStructKg`); trams are deferred to D6 with people, so D4 builds no tram verb, record, edge, row, test or visual (the REVISION's "[Q-B D6]" branches throughout). **What D4 builds.**
- **The gate is the colony's first fitted lift car** (`FitLift`, `Value` = the shaft). `HasTransit()` is "some shaft has a car"; with none, every line of D3 runs (the free, endless hoist, the instant head hand-off, every robot on the surface). The bill is `HasTransit() ? LiftFitStructKg : FirstLiftFitStructKg`, taken before the car is added, so the first fit's own take writes no ledger entry.
- **Capacity.** Every shaft has a places-a-sol capacity (an unfitted one is a 200-place hoist, a fitted one cars x 1,000). A place is one person or 100 kg of cargo; **a robot's body is 0 places** (REVISION item 4). Each shaft has an integer cargo ledger of three sol slots, written in any order, and its waits (`WaitSec`, `PrevWaitSec`) are frozen at a world-side sol threshold (`StepTransit`, straight after `StepUplink` in both bands). The roll reads the slot of sol s-2 and the people part from the commute flows, scaled by the ramp in permille (`2 x commuters x RampPermille / 1000`, floored once a shaft: 0 at 60 people or fewer, 1 place at 61, 320 at 160).
- **Every ledger event is stamped with its own step time** (item 2): a world-side bill (`TakeStructForBill`, growth bills, per source part to that source's serving shaft: O5) by `GetStepEndSeconds()`; a robot (boarding, the hand-off credit) by its own sub-step's end, `RH::RobotSubStepEnd` (one formula for both processors and the suite's driver). A robot reads a wait by that stamp with a 3.3 s guard after a boundary (`GetRobotWaitSec`), so robots-first and world-first batches of one frame read the same wait. `TransitUnstampedRobotWrites` counts the fallback and must stay 0.
- **The head hand-off pays its shaft** (item 6). A hauler that reaches a head with a cross-level drop holds there `10 x (wait + dwell + floors x seconds a floor)` sub-steps at idle draw and no wear (a runtime map in the sim, never saved, keyed to the task and the spot), then `HaulUnload(..., RobotLevel)` credits and charges the serving shaft the cargo's places. Both brains; both mid-delivery tests see the hold.
- **Robots below** (D3's design, carried): the deep planner (`PlanDeepRoute` over `FRHDeepNet`, wait-free; the robot's own waits are added at query time), rides (boarding ends a sub-step, the hold, `10 x (dwell + floors x 4)` ride sub-steps, Z flips at the end of the last), `RH::MoveAlong` routes through it with a target level, cross-level claims and the one ranking key (O9), the charge reserve below (`DeepReserveWh`: route-true, **every ascent hold priced at `MaxWaitSec`**, item 7), repair across floors for halted robots only, the load repair of robot levels (after floors, shafts, tunnels and cars are installed). **The first fit opens floor-level hauls to robots below** (no robot has ever claimed one; the fit alert says so, with the hoist's hold).
- **The commute.** With transit on, each underground end pays its shaft: `PerFloor(S)` (a hoist 6,000, a lift 2,000) plus its frozen wait at 100 cm a second. A trip between two floors is split over the shafts that reach the deeper one, **colonist k riding shaft R[k mod n]** (item 5, one pass); `PickCommuteShaft` adds the per-floor term (O4) and never a wait, so a crowd lengthens trips and never moves them (TR8b pins it). `FRHCommuteKey` gains `Lift` and `TransitWait`.

### Buttons fix and click test (2026-10-21, not yet committed)

Built from `docs/qa/2026-10-21/buttons-investigation.md`, which diagnosed why "none of the buttons worked" and designed the test. **Presentation only.** The sim, the save (v46), the data and every battery line are untouched.

**The bug.** `SRHMenus` is a full-viewport widget at Z 20, above the deck (Z 10), and its root took the Slate default `Visible`. Only its inner overlay collapses when no menu is open, so the root still swallowed every click, hover and wheel aimed at the deck, and each one fell through to `ARHPlayerController::OnClick` as a world click. Nobody had clicked the deck since the menus landed in `daaf86b` (10-15).

**Proved before it was fixed.** The click test was built first and run on the unfixed build: the title and pause menus passed (4/4 and 5/5 buttons reachable, NEW COLONY, CONTINUE and RESUME worked), and the deck failed with `REACH 0/65`, every miss `leaf=SRHMenus@RHPlayerController.cpp(56)`. 12 clicks reached `OnClick`, 2 of them on purpose. 16 of 26 steps failed. On the fixed build: `REACH 65/65`, 26 of 26 steps pass, 2 world clicks (both on purpose).

**The fix (4 changes).**
1. `SRHMenus` root `_Visibility = SelfHitTestInvisible`. The open screens keep their own `Visible` backdrops, so a title, pause or settings screen still swallows a click while it is up (the click test asserts all three).
2. `SRHCommandDeck` root the same, and `CloseMenus` restores `SelfHitTestInvisible`, not `Visible`. Only its panels and buttons take hits; the empty space between them reaches the world.
3. The deck now stops a press, release or wheel that lands on one of its panels and that no button took (`OnMouseButtonDown/Up/MouseWheel` return `Handled` on `SRHCommandDeck`; bubbling reaches a `SelfHitTestInvisible` root). Without this a panel click that no button takes bubbles up to the viewport and acts on the world: the click test with items 1, 2 and 4 but not this one fails `panel.blocks-world` and `leak.total` (a click on the OBJECTIVE title leaked). With it, clicking a panel no longer clears the selection or drops an armed build underneath.
4. `EndPlay` removes the Menus widget as well as the deck, so a level reload cannot stack a second one.

**The test (`Source/RedHope/Private/RHClickTest.cpp`, `scripts/unreal/rh_clicktest.sh`).**
- It walks the live Slate tree from the game window, arranging it top-down now (not reading each widget's last-painted geometry: a button scrolled out of its column keeps a stale position where another widget stands), and keeps only widgets inside every clip above them. It finds a button by its text, takes the centre, and asks `LocateWindowUnderMouse` what is there: `reached=YES|NO` and the leaf's type and creation site.
- It presses with real `FPointerEvent`s through `FSlateApplication` (move, down, up; a drag for the tunnel brush), so the press goes through hit-testing, capture and the viewport fallback like a hand. Two things were learnt the hard way: positions are desktop (tick) space, not paint space, and Slate re-sends a synthetic move to the OS cursor whenever the UI changes, which pulled the hover off the button before the release (a click needs `IsHovered()`). The test swaps the cursor user to Slate's faux cursor (`UsePlatformCursorForCursorUser(false)`) and places it at each press: the OS cursor never moves, and it swaps back at the end.
- `ARHPlayerController::WorldClickCount` counts `OnClick` calls. A button press that moves it leaked a click into the world and fails its step.
- Commands: `RH.Click <label> [nth]`, `RH.Hover <label>`, `RH.ClickSweep [why]` (`REACH n/m`, each miss with the widget in front of it), `RH.ClickText <label>`, `RH.ClickAt <fx> <fy>`, `RH.ClickWorld <Xm> <Ym>`, `RH.DragWorld <X0m> <Y0m> <X1m> <Y1m>`, `RH.ClickTest`. They queue and run a step at a time on the core ticker, so `-ExecCmds` can chain them.
- `RH.ClickTest` asserts: the title blocks a click; NEW COLONY; the deck sweep; an `OBJECTIVE` panel swallows a click; CONTINUE (`OnColonyReloaded` fires); the pause menu blocks, RESUME restores the speed it parked; the settings screen blocks; a BUILD tab opens the drawer, a card arms `SolarArray`, a ground click queues the Build; II, 3x, 8x, 60x, 1x set the clock; a manifest ADD (it meets Q1 first); Traffic on and off; the Tunnel button arms the brush and a drag queues a DigTunnel; the total of world clicks is exactly the two made on purpose.

**My own calls, for the director.**
- A dedicated script, not `rh_capture.sh`, because it needs `-RHTitle` and waits for a verdict line rather than screenshots. `rh_clicktest.sh` exits 0 only on `CLICKTEST RESULT PASS`. It parks the director's quicksave for the CONTINUE step and puts it back.
- The traffic legend is not asserted (the step checks the overlay flips). The first Power-tab and Solar Array card are pressed by their text, so a rename of either needs the script's label changed.
- A button that is greyed (disabled) is still counted by the sweep (geometry only) and skipped by `RH.Click` in favour of an enabled match.

- The test boots with `RH.Demo` and its sim state is throwaway; it does not touch `Saved/baselines`.


### D5 depth, depth has a price: what it settles, and where it deviated (2026-10-22, not yet committed)

Built from `docs/qa/2026-10-21/d5-depth-design.md`, in the order of authority the director set: the DIRECTOR ANSWERs, then the PROFESSOR RE-REVIEW conditions 1-5, then the REVISION (items 1-10 and the adopted O1-O8), then the PROFESSOR REVIEW, then the design. **Q-A (a), Q-B (a), Q-C (a):** shelter pays a Hope bonus capped at +3 for people homed below the cut-off, built like the window bonus; a cooling shortfall costs Hope only (up to -5) and is fully recoverable; the deep-home / surface-job net loss below -15 is accepted with no rule change (deep floors are for deep jobs). **The director's note, kept as asked:** Hope reaches arrivals and growth indirectly. Warmth costs Hope and nothing else directly, but like every Hope term it can slow settlers, births, the Big Arrival, disputes, discoveries, work tempo and city growth (new homes wait in the Failing band) while it lasts. No exemption is built: it would make warmth the only Hope term that immigration ignores.

**What D5 depth builds.**
- **The cut-off.** `DepthCostFromFloor` 5 (clamped 0..30). Floors -1 to -5 run today's code paths: every new branch tests `Level < -DepthCostFromFloor`, or a floor with cells below it, or a non-zero Warmth.
- **MaxDepth 20**, clamped to `RH::MaxDepthCap` 30 (the light key packs a bit a floor into a `uint32`).
- **Dig time.** An integer per-mille multiplier, `1000 + 150 x floors past -5`, fixed at batch start (bore, carve and tunnel cell by the floor the work is on; -6 is 13.8 h, -7 15.6 h, a carve on -6 3.45 h). Hydrogen and growth projects that carve scale with it. At or above the cut-off the batch hours and the fuel bill are the old expressions exactly (O1).
- **Cooling.** Every carved cell of a connected floor past the line (rated or not, tunnel cells included) asks `floors-past-the-line x 1 W` of the grid: one load entry a deep floor, `CoolingLoadPriority` 7, sorted after buildings and deepest first among equals. 100 cells on -6 are 100 W, on -10 500 W.
- **Warmth is driven by "the bank is scraping" (RE-REVIEW condition 1, the blocker's fix).** A step scrapes when (i) it starts with an empty bank and the full load is above generation (today's shed test) or (ii) the clamp would fire under the full load. The short floors are the cooling entries in the shed prefix of the priority walk over the full load, run whether or not the step actually sheds. A short floor warms at 1 / (`HeatRiseSols` x 1200) a second, every other floor cools at 1 / (`HeatFallSols` x 1200). Driven from the shed flag instead, Warmth never leaves its first step (about 8e-5 in the agent band): the -depth mutation shows it.
- **Hope.** `Shelter` = `HopeShelterMax` (3) x residents homed past the line / people, added straight after `Solidarity`; `WarmPenalty` = `HopeWarmMax` (5) x min(1, sum of residents x Warmth / people), subtracted straight after `CommutePenalty`. Both are +0.0 while nothing is deep or warm, so `Total` is bit-identical.
- **Save v47.** A warmth block straight after the transit block: a count, then (region, level, Warmth) per warm floor, shallowest first. The default colony writes 4 bytes. Structural refusals before any teardown; a level not past the cut-off (the row moved) is dropped with a Warning.
- **Presentation (placeholder, rows V1-V11 of `docs/qa/2026-10-15/gate-d-wording.md`).** The shaft strip's rows are in a scroll box capped at 11 rows (the SHAFT header and "Next shaft" above it, the lift card, the Tunnel brush and the tunnel list below it); choosing a floor scrolls its row into view; PageUp and PageDown step the view a floor (new Enhanced Input actions `IA_FloorUp` and `IA_FloorDown`). Floors past the line read their cooling (`-8 ▦30 ❄90 W`) and a warm one its share (` ≈14%`, amber text). The Bore button says its hours past the line. The folded POWER body reads "Cooling: N W for k deep floors", a circulator's card gains a DEPTH line, the CREW panel gains the Shelter and warm-floor lines. Floor tiles past the line darken a step per three floors and lerp toward a soft amber by Warmth, re-applied only when Warmth crosses a 10% step (the sim's `WarmthVersion`).

### D6a caverns: what it settles, and where it deviated (2026-10-22, not yet committed)

Built from `docs/qa/2026-10-22/d6-caverns-design.md`, section 1 of the MERGED DESIGN AND REVISION (every [RC n]), in the order of authority the director set: the DIRECTOR ANSWERs first. **Q-A (a):** reach, air, the Livable rating and the size minimum stay floor-wide through D8 (per-dig air and rating are deferred past step 2, not ruled out). **Q-B (a):** a cavern is up to 8 x 8 cells and 3 floors, carved with the ordinary 3 h `CarveCell` recipe; there is no new bill and no data row, so the limits are code constants (`RH::CavernMaxSide` 8, `RH::CavernMaxFloors` 3, `RH::MaxOpenCaverns` 2) and D6a touches no `docs/data` CSV or DataTable. **Q-C (a):** trams carry people only (D6d). This gate was started by one builder session and finished by a second; the second re-read every line against the spec (all items were present, one deviation fixed, see below).

**What D6a builds.**
- **`DigCavern` (Level = the top floor, Value = the number of floors, the two corners snapped by `CmToLattice`).** `CanDigCavern` is the preflight, run at queue time (the player controller's ghost uses the same function) and again at execute time, with all seven refusals each carrying a reason: (1) the deepest floor is reached by no shaft; (2) a side over 8, more than 3 floors, or below `-MaxDepth` (sides are checked in 64 bits, so an absurd point is a refusal, not an overflow); (3) a box point is a shaft column; (4) a box point is an uncarved point of an open tunnel or of another open cavern; (5) **one seed per floor**: on every floor of the box some uncarved point must be eligible; (6) more than 2 open; (7) every point already carved. `CanDigTunnel` refusal 6 and the sink-column check (`CheckSinkColumn`, SinkShaft refusal 8) gain "an uncarved point of an open cavern". `CancelCavern` (Value = Id) works like `CancelTunnel`: no new batch starts, carved cells stay, a batch in flight lands its cell. Ids are dense and never reused; `ShaftId` is fixed at execute time (the nearest shaft that reaches the bottom floor, ties to the lower Id, helper Borers count as shaft 0).
- **`FRHCavern`** (saved: Id, RegionId, ShaftId, Top, Bottom, Min, Max, bCancelled; derived and never saved: the uncarved count per floor keyed on `FloorCellsVersion`, and `bFinished`).
- **Eligibility is horizontal only (RC 2):** an uncarved, non-column point is eligible when it is 4-adjacent to a carved cell on its floor or to the column of a shaft that reaches that floor. Cells are never removed, so a point that is eligible once stays eligible.
- **One carve helper (RC 3), `CarveLatticePoint(Level, P)`:** refuses a column or a carved point before touching anything, removes the point from `Plan` (a carved point in the plan is a refused save), then appends through `AppendCarvedCell`. It is the only new path that appends a cell; ordinals stay add-only.
- **One predicate each (RC 1).** `RH::IsTunnelWork` (X is 2 or 3) and `RH::IsCavernWork` (X >= 100) replace every `X >= 2` reader: completion (cavern branch first, then tunnel), the batch-start log (caverns get their own line), `GetTunnelBatchesInFlight`, D5's batch-start dig pricing (a cavern batch reads its floor from `X = 100 + depth`) and its start-log branch. `grep -rn "\.X >= 2\|->X >= 2" Source/RedHopeSim` finds nothing (the five remaining hits for `X >= 20` are the suites' own lattice test).
- **`FindCavernWork`** runs after `FindTunnelWork` and only with a cavern on the list: open caverns by Id for this Borer's shaft, on the shallowest floor that has an eligible point and more uncarved points than batches in flight. **Completion** appends the eligible point lowest by (X, then Y) through `CarveLatticePoint`; if none is left it drops the spoil, adds no cell and prints a line.
- **Save v48.** A cavern block straight after D5's warmth block (NextCavernId, the count, then 40 bytes a record; the default colony writes 8 bytes), read into locals before teardown. Every structural refusal goes through `OutError` ("Save cavern list invalid: ..."), never an Error line: ids not ascending or not below the next Id, a region other than 0, a level outside `-MaxDepth..-1` or reached by no loaded shaft, a side or floor count over its limit, a box point on a column (a cancelled cavern is exempt: its rock may be sunk on later), two open caverns or an open cavern and an open tunnel sharing an uncarved point, a count over `MaxCavernRecords` or larger than the bytes left. The Warning repair: a work record with X >= 100 that names no cavern, or a floor outside its box, completes with spoil and no cell.
- **Presentation (placeholder; rows J1-J10 of `docs/qa/2026-10-15/gate-d-wording.md`, a fresh prefix).** `URHCavernVisualizerSubsystem` (a pure listener, `RedHopeSim` does not know it): the uncarved points of the box are a dashed teal ghost with a faint fill, the box a thin teal outline, a label over it; redrawn only when the cavern list, the floor table, the shaft list or the viewed floor changes. The Cavern brush (the shaft strip's Cavern button; a second press steps the height 1..3 floors, the press after the last disarms) is a box variant of the tunnel brush: the ghost runs the sim's own preflight, green accepts, red names the refusal, and the tip quotes the bill (cells, Borer-hours, spoil, O2 to fill). Under the button, the viewed floor's open caverns each with what is left and a Cancel. Console: `RH.DigCavern`, `RH.CancelCavern`, `RH.CavernNow`, `RH.CavernGhost`, and a line per cavern in `RH.Status`.

**Deviations.**
1. **The limits are code constants, not `RH_Config` rows** (Q-B (a), superseding the design's "Rows" line). No CSV, no DT sync.
2. **A work record of no known kind** (X from 4 to 99, only a hand-made file can hold one) now completes with spoil and no cell and a Display line. Before D6a the final `else` carved a cell for it. No saved record can be of that kind, so every existing log is unchanged.
3. **The Warning repair fires when the batch lands**, not at load: the load keeps the work record as written and the completion branch finds no cavern (or a floor outside its box) and logs a Warning. The outcome the spec asks for (spoil, no cell) is the same; the colony is never torn down for it.

5. **Test-only hooks:** `Debug_DigCavern` (the order without the uplink, same preflight and execution) and `Debug_CarveCavernCells` (the same completion a finished batch takes); both also back `RH.CavernNow` and the `-scale` block.

### Perf fix before trams: the three D4 budgets at 20 floors, a pure performance change (2026-10-22, not yet committed)

D6a's `-scale` run missed three D4 budgets at 20 floors (cold deep net 5.51 ms against 3, 2,500 `PlanDeepRoute` 25.5 ms against 10, flows only with 2,000 deep residents 1.023 ms against 1). This gate fixes all three with **no behaviour change**: no save bump, no data row, no budget number moved, nothing the suite measures changed, and none of the three forbidden shortcuts (a whole-query memo, all-pairs portal tables, A*) was used. Source touched: `RHSimTransit.cpp`, `RHSimCommute.cpp`, `RHSimWorldSubsystem.h`. Nothing in `Source/RedHope`, so no click test.

**What changed.**
- **Cold deep net (`EnsureDeepNet`, `BuildLatticeNeighbours`).** The neighbour table reads a flat grid over the floor's bounding box (`FTransitFlatIndex`, a reused buffer; the hash stays as the fallback when the box is over 64 x the cell count + 4,096), the four orthogonals found once and the diagonals read from them. One heap and one grid buffer are reused across all 80 fields (`RunLatticeField`; `BuildLatticeField` with a table now calls it too). The surface-leg memo (`SurfaceRoutes`) is kept across a rebuild while `RoadGraph.BuiltVersion` is the one it was planned under (`BuiltVersion` only ever rises, a load resets the net, and the memo is a pure function of the built graph). **Not done:** per-floor caching of fields or tables (not needed; every budget passes without it).
- **`PlanDeepRoute`.** A binary heap keyed (distance, node index) with lazy deletion (`FTransitSearch`: raw arrays, a hand-written sift; the pop order is the strict total order alone, and every pair is pushed once, so it pops exactly the sequence the old linear scan did). The edge prices are stored in the net (`FRHDeepNet::Edges`, parallel to the old `Adj`, which is gone: kind, floors or lattice cm or head cost) and the robot's wait is read once a shaft a call (`RideShaftUnits[S] + RideFloorUnits x floors`, the same integer as the old `RideUnits`); each node's edges are priced once, when it settles; the start relaxes only the heads, the portals on its level, or its column; the end is priced from the popped portal alone. Portals are indexed by level (`LevelPortals`, filtered on column or dig: `FindPortalColumnAt` scans one short list); inline capacity 512 nodes (the worst case is 498) and 256 heap items, a 32-slot chain, the three path arrays reserved to 64. Every tie-break, the strict-improvement relaxation and the iteration order are unchanged.
- **Flows (`DeriveCommuteFlows`).** The shaft of a floor-to-surface trip is picked once and passed to `GetCommuteDistanceVia` (the public `GetCommuteDistanceCm` calls it with no known shaft); `LongIds` is sorted only when it is out of order (it never is in a real colony); `Ids`, `Dists`, `LongIds`, `Trips`, `TripIndex` and the two transit trip arrays are reserved (the trip count from the last derive, 64 at least).
- **`-RHVerifyCaches` covers the one new cache.** A `SurfaceRoute` memo hit re-plans the leg and compares it (`RHVERIFY: the deep net's surface leg ... is stale`).
